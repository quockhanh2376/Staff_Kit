# Staff Kit v2.2.1 Release Notes

**Release Date:** October 17, 2026  
**Version:** 2.2.1  
**Build Target:** Windows x64 (Tauri v2, WebView2, SQLite)

Staff Kit v2.2.1 is an official stable release bringing enterprise-grade synchronization enhancements, full HR employee lifecycle governance, non-destructive floating overlay support, rock-solid security boundaries, startup paint optimization, and refined LAN borrow/return flows.

---

## Key Highlights & Feature Details

### 1. Config Sync
- **Modernized Collapsible Card:** Styled identically to the Admin Portal with an emerald database badge, rounded card surface, smooth expand/collapse height/opacity animations, and idle auto-collapse.
- **Keyboard & ARIA Accessibility:** Header implemented as a semantic button with explicit `aria-expanded` and `aria-controls="config-sync-panel"`. Supports full keyboard navigation with Enter/Space toggling and emerald `focus-visible:ring-2` outline. Collapsed state applies `visibility: hidden` (`invisible`) and `pointer-events-none` to prevent hidden form inputs from trapping keyboard focus.
- **Streamlined Configuration:** Compact single-row layout for Server, SQL Username, Password, Save button, and Test Connection. Default port (1433) and database (AssetManagement) are sensibly defaulted with advanced override options.

### 2. Remote EE Sync & HRMS Integration (Query B)
- **Fixed CTE SELECT-only Sync:** Canonical employee synchronization relies exclusively on embedded Query B CTE against `dbo.Staffs` and `dbo.AspNetUsers`. User-supplied or modifiable SQL is strictly prohibited.
- **Fail-Closed Permission Gate:** Enforces read-only permissions with exact-match approved login (`user_reader`) and immediately fails closed on any write, `ALTER`, `CONTROL`, or DDL privileges.
- **Credential Isolation:** SQL credentials are encrypted and stored exclusively in Windows Credential Manager via Windows DPAPI. No plaintext credentials are ever stored in SQLite, log files, configuration exports, or source code.
- **Reporting Missing Records:** Employees present in local database but absent from Query B (e.g. ASWVN1145) are reported for review without automated offboarding or destructive mutations.

### 3. Complete HR Lifecycle State Management
- **Lifecycle States:** First-class support for all canonical lifecycle statuses:
  - `active`
  - `pending`
  - `offer_rejected`
  - `resigned`
  - `rehired`
  - `transferring`
- **Explicit User Confirmation:** Transitions such as offer rejection, offboarding, rehire, and internal transfer require explicit user approval dialogs before any change is recorded.
- **Audit & Historical Integrity:** Staff IDs, employee identifiers, audit trails, team history, and historical asset records are preserved across transitions.

### 4. Non-Destructive Floating Overlay
- **Unified Master with Overlay:** Floating is managed via a non-destructive flag (`is_floating = 1`) over the single canonical employee record rather than a segregated table or loss of master status.
- **Bidirectional Visibility:** Floating employees remain fully visible in the Employee List and simultaneously synchronize with the dedicated Floating view.
- **Preserved Staff Groups:** Preserves standard canonical staff groups (Management, Delivery, Technology, Support) alongside floating assignments.

### 5. Preview-Before-Write Protection
- **Streamlined Sync Actions:** EE Sync preview presents two explicit choices: `Skip | Approve`.
- **Approval Gating:** The `Approve` action is enabled only when importable changes exist (`New + Changed > 0`) and zero blocking conflicts remain.
- **Zero-Write on No-Op:** Applying a sync with no changes or skipping clears preview without issuing database writes or IPC mutations, guaranteeing zero-write transactional safety on repeated syncs.

### 6. Startup Paint Synchronization
- **Elimination of Black Screen:** Synchronized WebView first-frame paint lifecycle. The native window remains hidden until the initial frontend frame completes rendering with the configured dark theme background (`#0d0d0d`), ensuring instant, flicker-free startup.

### 7. LAN Borrow/Return Workflows
- **Canonical Identity Normalization:** Standardizes employee name, email, and staff ID matching across local network borrow/return interactions.
- **Inline Signature Mirroring:** High-fidelity live mirroring of signatures across connected devices.
- **Compact Signature Box:** Redesigned responsive signature capture pad optimized for touchscreen and pointer input without modal obstruction.
- **Fixture Cleanup:** Cleaned up legacy test fixtures and hardened borrow/return transactions against concurrent state changes.

---

## Security & Architecture Protections

- **Single Master Employee Identity:** Enforces one canonical employee per Staff ID (`EE.ID`).
- **Asset Loan Governance:** Hardware assignments are strictly bound to active `asset_loans` records, ensuring multi-device tracking integrity (Device 1 & Device 2).
- **System-Trusted TLS Validation:** All remote database connections require system-trusted TLS certificate validation; `TrustServerCertificate` remains strictly prohibited.
- **Protected Storage:** SQLite database encryption and DPAPI isolation safeguard sensitive workforce data at rest.
