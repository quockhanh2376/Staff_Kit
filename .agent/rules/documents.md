# Document Rules (StaffKit)

## Purpose

Keep project documentation consistent, short, and easy to maintain.

## Source Of Truth

- Product/feature baseline: `Note.md`
- Technical baseline: `Tech_tags.md`
- Agent behavior baseline: `.agent/project-context.md`

## Placement

- Short planning notes: keep in repo root only when explicitly requested.
- Structured docs: use `docs/` (create only when needed).
- QA artifacts: use `docs/qa/` if QA docs are requested.

## Format

- Use Markdown.
- Start with clear title and date when useful.
- Prefer checklists and acceptance criteria.
- Keep docs focused on actionable content, avoid long narrative text.

## Update Policy

- Update existing docs instead of creating duplicates.
- If a document is obsolete, mark it as superseded and point to replacement.
